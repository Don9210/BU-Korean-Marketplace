# 기능 2 · 물건 등록·수정·삭제

`글쓰기`에서 사진 1~3장, 제목, 가격, 카테고리, 거래 장소, 설명을 입력합니다.
저장하면 `내 활동 → 내 판매 글`로 이동합니다. 글을 누르면 수정하거나 삭제할 수 있습니다.
검색·필터, 상세/댓글, 거래 상태 변경, 평점은 이번 작업에 포함하지 않았습니다.

## Supabase 준비

1. [기능 1 설정](auth-setup.md)을 완료하고 실제 BU 계정으로 로그인합니다.
2. 기존 `supabase/schema.sql`이 적용되어 있는지 프로젝트 담당자가 확인합니다.
3. 담당자가 SQL Editor에서 **`supabase/listing-images-policy.sql`**을 실행합니다.
   기존 테이블을 바꾸지 않고 본인 사진의 SELECT 정책을 추가합니다.
   Storage에서 사진을 삭제할 때 기존 DELETE 정책과 함께 사용합니다.
4. Storage의 `listing-images` 버킷과 사용자 ID별 업로드/삭제 정책을 확인합니다.
   버킷의 업로드 한도는 압축 후 사진당 5MB이고 허용 형식은 JPEG, PNG, WebP입니다.

등록 시 사진은 브라우저에서 긴 변 1600px 이하의 JPEG로 압축합니다.
JPG, PNG, WebP를 선택할 수 있으며 HEIC는 JPG로 변환한 후 선택합니다.
사진 경로는 `<사용자 ID>/<고유 파일 이름>.jpg`이며 기존 파일을 덮어쓰지 않습니다.
사진 URL은 기존 공개 버킷 정책을 따릅니다.

가격은 달러 정수이고 0은 무료 나눔입니다. 제목 1~60자, 설명 최대 2,000자는 기존 DB 제한에 맞췄습니다.
등록 시 `seller_id`는 로그인한 사용자 ID를 사용합니다. 수정·삭제에는 사용자 ID 필터와 기존 DB 접근 규칙(RLS)을 함께 적용합니다.
구매자가 확인한 거래는 기존 DB 규칙에 따라 삭제할 수 없습니다.

## 실제 BU 계정 2개 테스트

계정 A는 일반 브라우저, 계정 B는 시크릿 창이나 다른 브라우저에서 로그인합니다.

| 절차 | 기대 결과 |
|---|---|
| A가 사진 없이 등록하거나 4장을 선택 | 사진 1~3장 안내, 저장 안 됨 |
| A가 사진 1장/3장으로 각각 등록 | 내 판매 글에 나타나고 새로고침 후에도 유지 |
| 음수·소수 가격 입력 / 0 입력 | 음수·소수 거부, 0은 무료 나눔 |
| A가 자신의 글에서 제목·가격·설명 수정 | 새 내용이 저장됨 |
| 사진 1장 삭제 후 다른 사진 추가 | 남긴 사진 유지, 새 사진 표시, 제거한 사진 정리 |
| B가 내 활동 방문 | B의 글만 보임 |
| B가 A의 `/listings/<ID>/edit` 주소 직접 방문 | 글이 없거나 권한이 없다는 안내, 수정·삭제 불가 |
| A가 글 삭제를 눌렀다가 취소 | 글과 사진 유지 |
| A가 삭제 확인 | 내 판매 글에서 사라지고 관련 사진 정리 |
| 업로드/저장 중 네트워크 오류 후 재시도 | 실패 안내, 내 활동에서 저장 여부 확인 가능 |

브라우저 화면 외에도 프로젝트 담당자가 **B의 실제 로그인 토큰을 사용하는 API 요청**으로 A의 글 수정·삭제가 거부되는지 확인합니다.
SQL Editor의 관리자 권한은 RLS를 우회하므로 이 테스트를 대신할 수 없습니다.

## 실패 시 사진 처리

일부 업로드 실패나 명확한 DB 거부 시 이번에 추가한 사진을 정리합니다.
저장 응답만 유실된 경우에는 글을 다시 읽어 성공 여부를 확인합니다.
네트워크가 계속 끊겨 저장 여부를 확인할 수 없을 때는 이미 저장된 사진을 잘못 지우지 않도록 보존합니다.
이 경우 사용자는 내 활동에서 글 저장 여부를 먼저 확인하고, 담당자는 필요하면 미사용 파일을 정리합니다.
글 저장과 Storage 삭제는 별도 요청이므로 사진 정리에 실패해도 성공한 글 저장을 취소하지 않습니다.

실제 Supabase 업로드·운영 DB 권한 검증은 아직 수행하지 않았습니다.
로컬 모의 API 테스트는 실제 BU 계정 2개 테스트를 대신하지 않습니다.
